# Problem Statement

An end user may find themselves unable to effectively participate at all in their capstone duties, or being treated as a different student with the same name as them. This is due to the capstone site's roster: The student roster on the Capstone website relies on a redundant copy based on data from Panthersoft, including the student information that's necessary for the roster's continued maintenance. However, this copy can prove to be unreliable as it's not directly connected to the source, and issues such as students that aren't actually in the system being treated as they are in the system and slow overall updates of the roster can cause the capstone site to ultimately be unreliable and risky to rely on identity-wise. This matters to the users, as the roster system needs to be reliable enough to not deteriorate their capstone semester with issues that they can only notify an administrator about, and site administrators themselves, who by hand need to ensure that the roster with hundreds of entries isn't creating these issues.

## Scope

A basic roster system that can be built on. It runs on simulated data and does not connect to Panthersoft.
